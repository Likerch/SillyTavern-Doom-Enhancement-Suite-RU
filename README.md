# SillyTavern - Doom's Enhancement Suite - RU

Надстройка для SillyTavern поверх [Doom's Enhancement Suite](https://github.com/DangerDaza/Dooms-Enhancement-Suite) (DES):
русский интерфейс DES и исправления трекера для ролеплея на русском. Плюс лорбуки
[BunnyMo](https://github.com/Coneja-Chibi/BunnyMo) и расширение [CarrotKernel](https://github.com/Coneja-Chibi/CarrotKernel),
которые без неё в русской игре работают наполовину.

> **Это надстройка, а не форк.** В репозитории нет кода DES, CarrotKernel и лорбуков BunnyMo, и ни один их файл
> не меняется. Они ставятся и обновляются отдельно, из своих репозиториев. Надстройка работает с ними через DOM,
> события SillyTavern и публичные экспорты их модулей.

**📖 Подробная инструкция — в [docs/guide](docs/guide/README.md).**

## Что умеет

| Модуль | Коротко | Инструкция |

| 1. Локализация интерфейса | Весь интерфейс DES по-русски: настройки, окна, «Мастерская», лист персонажа, трекер сцены, уведомления. Свой словарь и выгрузка непереведённого | [подробнее](docs/guide/module-1-localization.md) |

| 3. Служебные значения | Эффекты погоды и смена дня и ночи работают с русскими значениями: «моросит», «вьюга», «безоблачно» | [подробнее](docs/guide/module-3-service-values.md) |
| 4. Исправления DES для русского | Кириллические названия полей, «не в сцене», «квеста нет», переводы встроенного переводчика ST, картинки в пузырях чата, пузыри без похода в редактор, пресет трекера остаётся у своей карточки | [подробнее](docs/guide/module-4-fixes.md) |

## Требования

- **SillyTavern 1.19.x.**
- **Doom's Enhancement Suite** — для модулей 1–4. Проверено на 2.6.0 (коммит `10ad241`).
- По желанию: **лорбуки BunnyMo** (проверено на V3.0 и паках «BunnMo Packs») — для модуля 5, и **CarrotKernel**
  (проверено на 1.0.0) — для модуля 6.

## Быстрый старт

1. Поставьте DES: **Extensions** → **Install Extension** → `https://github.com/DangerDaza/Dooms-Enhancement-Suite`.
2. Поставьте надстройку тем же способом:
   ```
   https://github.com/Likerch/SillyTavern-Doom-Enhancement-Suite-RU
   ```
3. Перезагрузите страницу. В **Extensions**, под блоком DES, появится панель надстройки со статусом «работает».
4. В настройках DES выберите режим генерации **«Вместе с ответом»**: в нём работают все возможности.

Подробно — в [Установке](docs/guide/installation.md), а как играть со всем набором — в [Как играть](docs/guide/playing.md).

## Совместимость

- **Режимы DES.** Всё работает в режиме «Вместе с ответом». В «Отдельным запросом» и «Внешний API» нет склейки форм
  имён и подсказок модели, остальное работает. Подробнее — в [таблице](docs/guide/compatibility.md#режимы-des).
- **Qvink Memory** совместим. Как настроить его для русской игры с DES — в
  [Совместимости](docs/guide/compatibility.md#qvink-memory).
- **NAI Studio** — с версии 0.9.3. **LorebookLocalizer** — совместим.

## API для Maestro

Для расширения-«дирижёра» [Maestro](https://github.com/Likerch/SillyTavern-Maestro) и мастерской Officina надстройка
выставляет `globalThis.DESRU_API`. Объект появляется при запуске надстройки и убирается, когда её выключают в менеджере
расширений ST (хук `disable` в `manifest.json`). Он версионный: в версии 1 поля только добавляются, а что добавилось
после 0.8.0, перечислено в `features`.

```ts
interface DesRuApi {
    version: 1;
    features: readonly string[];                // 0.9.0: 'trackerPresets', 'trackerBindingByAvatar'
    nameForms(name: string): string[];          // все падежные формы имени, первой — само имя
    nameFormsKey(name: string): string | null;  // ключ-регулярка ST (/…/iu) на все формы
    aliases(): Record<string, string[]>;        // алиасы DES: имя карточки → алиасы (копия)
    onNamesChanged(listener: () => void): () => void;  // надстройка изменила алиасы или скрытые имена; возвращает отписку
    functions(): string[];                      // функции, которые Maestro может взять на себя
    setMaestroOwned(ids: string[]): void;       // какие из них сейчас у Maestro (замена списка)
    maestroOwned(): string[];
    trackerPresets: TrackerPresets;             // 0.9.0, см. «Пресеты трекера для Officina»
    trackerBinding: TrackerBinding;
}
```

- **Склонения.** `nameForms` и `nameFormsKey` работают и без DES. Формы — для поиска имени в тексте: среди них есть
  и такие, что совпадают с другим именем («Александра» у «Александр», «Петрова» у «Петров»), поэтому алиасами DES
  их делать нельзя. У имени из нескольких слов — все сочетания форм слов. Регистр и «ё» имени сохраняются.
- **Алиасы** читаются из DES, пока гард разрешает работу с его данными; иначе — пустой объект.
  `onNamesChanged` срабатывает, когда модуль 2 дописал (в том числе кнопкой «Склеить») или убрал алиас, спрятал
  форму имени игрока или убрал заготовку карточки DES. Правки самого пользователя в «Мастерской» DES сюда не попадают.
- **Согласование функций.** Пока функция у Maestro, надстройка её пропускает:

  | id | Что надстройка перестаёт делать | Что остаётся |
  |---|---|---|
  | `bunnymo.structuralPatches` | Модуль 5 не ставит записям BunnyMo флаги рекурсии: `excludeRecursion` детекторам и «анти-клэнкеру», `preventRecursion` записям Kaomoji Library, Medicine Check и LINGUISTICS | Русские ключи детекторов, текст «анти-клэнкера», архетипы, падежи в ключах архивов |
  | `bunnymo.scanTags` | Модуль 5 не пишет теги персонажей сцены во вставку «только для сканирования» | Теги по-прежнему запоминаются в чате; вернул Maestro функцию — вставка сразу снова заполнена |
  | `ck.consistencyRebuild` | Модуль 6 не пересобирает вставку тегов CK («Character Consistency») | Свой поиск персонажей в листах и макросах CK, RAG по падежам, дамп и интерфейс CK |

  По умолчанию все функции у надстройки, и она работает как раньше. Ничего не сохраняется: Maestro объявляет свои
  функции при каждом запуске. Незнакомые id пропускаются. Что сейчас у Maestro, видно в замечаниях модулей 5 и 6 на
  панели.

### Пресеты трекера для Officina

С 0.9.0 (`features` содержит `'trackerPresets'` и `'trackerBindingByAvatar'`). Officina публикует пресет трекера DES
для карточки и привязывает его к карточке **по аватару** (имени файла карточки), а не по номеру, как DES.

```ts
type Result = { ok: true } | { ok: false; error: string; errors?: string[] };

interface TrackerPresets {
    list(): { id: string; name: string }[];                         // пресеты DES в его порядке
    get(id: string): { id: string; name: string; trackerConfig: object } | null;  // копия
    validate(trackerConfig: unknown): string[];                     // ошибки; [] — можно записывать
    save(preset: { id?: string; name: string; trackerConfig: object }): { ok: true; id: string } | Result;
    remove(id: string): Result;                                     // вместе с привязками, как в DES
}

interface TrackerBinding {
    active(): boolean;                                   // работает ли привязка по аватару
    get(avatar: string): string | null;                  // id пресета карточки
    set(avatar: string, presetId: string | null): Result;  // null — снять привязку
}
```

- **`save`** без `id` (или с новым `id` из латиницы, цифр и `_ . : -`) создаёт пресет, с `id` существующего —
  заменяет его имя и `trackerConfig`. Новый пресет, как у DES, получает копию текущих настроек «истории»
  (`historyPersistence`), у заменяемого они остаются свои. Если заменили активный пресет, DES тут же загружает его
  заново. Ничего не пишется, если что-то не так: `{ ok: false, error: 'invalid', errors: [...] }` — по-русски, с
  путём до поля.
- **Проверка `trackerConfig`** (DES 2.6.0): `infoBox.widgets` с известными виджетами DES (`date` обязателен),
  `presentCharacters.customFields` — массив **не больше 8** полей (в самом DES предела нет, это договорённость с
  Officina), `id` и ключи полей без повторов, свои поля сцены — латиницей и без встроенных ключей (иначе DES молча их
  выбрасывает), текст, который DES вставляет в шаблон трекера как есть, — без двойных кавычек и `\`, весь объект —
  JSON до 200 000 знаков. Старые пресеты с лишними полями проходят.
- **`trackerBinding.set`** работает, пока включён переключатель модуля 4 «Пресет трекера — у своей карточки»
  (`active()`); иначе `error: 'off'`. У открытой карточки DES сразу выбирает пресет заново. `get` при выключенном
  переключателе отвечает, что DES выберет для карточки по её нынешнему номеру.
- **Коды ошибок:** `unavailable` — DES или его пресеты недоступны (гард остановил работу с данными DES);
  `editor-open` — открыт редактор трекера DES (он сохранит своё поверх, повторите после его закрытия); `not-found` —
  нет такого пресета; `last` — последний пресет DES не удаляет; `no-card` — карточки с таким аватаром нет.
- Привязки групп DES (`group_<id>`) стабильны, API их не трогает.

## Приватность

Никакой телеметрии и внешних запросов. Сама надстройка загружает только свои словари с того же сервера SillyTavern.
Настройки хранятся в `extension_settings.desru`. Что надстройка записывает в данные DES и CK, перечислено в
[Совместимости](docs/guide/compatibility.md#что-надстройка-меняет).
